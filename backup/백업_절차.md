# TW Project Manager — 백업 절차 (취합본)

> 마지막 정리: 2026-07-21

이 문서는 백업/복원과 관련된 모든 절차를 한곳에 모은 마스터 문서입니다.

---

## 1. 백업의 3가지 대상

| 대상 | 어디에 있나 | 백업 방법 |
|------|-------------|-----------|
| **코드** (index.html) | git 저장소 + 파일 | git commit/tag + backup 폴더 복사 |
| **데이터** (프로젝트 목록) | 각 브라우저 localStorage + 공유 Firebase | Ctrl+S/업로드 시 자동 JSON 다운로드 |
| **복원 안내** | 없음 | 날짜 폴더에 Restore txt 작성 |

- **Firebase**: 가장 마지막에 업로드한 상태 **1개만** 남음 (이력 없음, 팀 공유, last-write-wins).
- **로컬 JSON 백업**: **저장을 누른 사람 컴퓨터**의 다운로드 폴더에만 생성됨 (`tw_pm_backup_날짜_시각.json`).

## 2. "백업" 명령 시 절차 (날짜별 폴더 방식)

**원칙: 그날 백업과 관련된 파일은 전부, 예외 없이 `backup/YYYY-MM-DD/` 폴더 하나에만 모은다.**
`backup/` 바로 밑(루트)에는 그 날짜 백업의 파일을 직접 놓지 않는다 — 코드 스냅샷, Restore 안내문, 데이터 JSON까지 전부 같은 날짜 폴더 안에 들어가야 한다. 기존에 이미 있던 다른 날짜 폴더/파일은 그대로 둔다.

1. **날짜 폴더 생성** — 이름 규칙:
   - **그날 첫 백업**: `backup/YYYY-MM-DD/`
   - **그날 두 번째 이상 백업** (같은 이름의 날짜 폴더가 이미 있으면): `backup/YYYY-MM-DD_HHMM_키워드/`
     - `HHMM`: 지금 시각 (예: `0526`, `0948`)
     - `키워드`: 그 백업 시점까지 작업한 내용을 짧은 영문 kebab-case로 요약 (예: `dashboard_for_report`, `sync-fix`)
     - 예시: `backup/2026-07-11_0526_dashboard_for_report/`, `backup/2026-07-13_0948_sync-fix/`
   - 백업 시작 전, `backup/` 안에 오늘 날짜로 시작하는 폴더가 이미 있는지 먼저 확인해서 규칙을 적용한다.
2. **코드 스냅샷 복사**: `index.html` → 위에서 만든 폴더 안에 `index_backup_YYYYMMDD_stable.html` (시간/키워드가 붙은 폴더여도 파일명은 날짜 기준으로 통일)
3. **git 커밋 + 태그** (main 브랜치):
   ```
   git add index.html
   git commit -m "..."          # 그날/그 시점 작업 요약
   git tag stable-YYYYMMDD          # 그날 첫 백업
   git tag stable-YYYYMMDD-HHMM     # 같은 날 두 번째 이상 백업 (태그 이름 중복 방지)
   ```
4. **작업 내역 정리**: 이 문서의 **섹션 7(작업 이력)**에 날짜(및 여러 번째면 시각)·작업 목록 추가
5. **Restore 안내 파일 작성**: 위 1번에서 만든 폴더 안에 `Restore from a backup_YYYY-MM-DD.txt` (시간/키워드 폴더면 `Restore from a backup_YYYY-MM-DD_HHMM.txt`)
   (아래 항목 포함: 백업 날짜/시각 / git commit / git tag / 백업 파일명 / 코드·데이터 복원법 / 주요 작업 목록)
   → **루트가 아니라 반드시 1번에서 만든 그 폴더 안에 작성.**
6. **데이터 JSON도 같은 폴더로**: 사용자가 브라우저에서 **Ctrl+S**를 눌러 생성된 `tw_pm_backup_*.json`을 **같은 폴더 안으로** 옮겨 넣으면 그 백업이 완성됨 (코드 + 데이터 + 복원 안내가 폴더 하나에 전부 모임).
   > Claude는 브라우저 데이터에 직접 접근 불가 → 데이터 JSON은 반드시 사용자가 브라우저에서 저장 후 그 폴더로 옮겨야 함.

**완성된 폴더 안에 있어야 할 파일 (예시, `backup/2026-07-21/` 또는 `backup/2026-07-21_1430_op-task-parity/`):**
- `index_backup_20260721_stable.html` (코드 스냅샷)
- `Restore from a backup_2026-07-21.txt` (복원 안내)
- `tw_pm_backup_2026-07-21_*.json` (데이터 백업 — 사용자가 옮겨 넣음, 있으면)

## 3. 일상 데이터 백업 (자동, 폴더 지정 방식)

- **업로드 버튼(↑) 또는 Ctrl+S** → Firebase 업로드 + **지정 폴더**에 `tw_pm_backup_날짜_시각.json` 자동 저장.
- **저장 폴더 지정 (최초 1회):** 처음 업로드하면 폴더 선택창이 뜸 → `TW_Project_Manager\Upload to Firebase` 폴더 선택. 이후엔 자동으로 그 폴더에 쌓임. 툴바의 **폴더 아이콘 버튼**으로 언제든 변경 가능.
- 형식: `{version, exportedAt, projects, deletedProjects, records, recordMemos}` → 앱의 가져오기(↑)로 복원 가능.
  - `records`: Record 페이지에 저장된 캡처 이미지(base64) 전체. `recordMemos`: 날짜별 메모.
  - 캡처 이미지가 많으면 JSON 파일 용량이 커질 수 있음(이미지가 base64로 그대로 포함됨).
- **Dashboard 전체 캡처**: Dashboard 페이지 상단의 **"전체 캡처"** 버튼 → 5개 하위 페이지(Delivery Acceleration/In Active/준비 중/Resource/Completed)를 자동으로 순회하며 모두 캡처해서 Record 페이지의 **오늘 날짜(기록 기준일) 그룹**에 한 번에 저장. 이 캡처들도 위 JSON 백업(`records`)에 그대로 포함됨.
- 중요한 변경 후에는 **각자 한 번씩 Ctrl+S** 권장 (백업은 누른 사람 로컬에만 생김).
- 브라우저 제약: Chrome/Edge만 폴더 지정 지원. 새 브라우저 세션에서 첫 저장 시 폴더 접근 재확인 프롬프트가 뜰 수 있음(Allow). 미지원/거부 시 다운로드 폴더로 저장.
- 수동 추출 도구: `backup/export_localStorage.html` (Firebase 미연결, localStorage만 읽어 다운로드).

## 4. 복원 방법

### 코드 복원
- **Git tag (추천)**: `git checkout stable-YYYYMMDD -- index.html`
- **파일 복사**: `backup/YYYY-MM-DD/index_backup_*.html` → `index.html`로 덮어쓰기

### 데이터 복원
1. 앱을 브라우저에서 연다
2. 가져오기(↑) → 복원할 `tw_pm_backup_*.json` 선택 → 확인
3. **Ctrl+S**로 Firebase에 다시 업로드(팀 공유본 복원)
4. Ctrl+Shift+R 새로고침

## 5. 안전장치 (사고 방지)

- Firebase가 비어 있으면(0건) 로컬에 데이터가 있는 한 **덮어쓰지 않음** (실시간 리스너 + 폴링에 가드 적용).
  → 실수로 Firebase가 통째로 비워져도, 로컬이 살아있으면 화면에 유지되고 Ctrl+S로 복원 가능.
- **주의**: 실제 Firebase에 연결되는 index.html을 새 주소(예: localhost 서버)에서 브라우저로 열면 최초 실행 마이그레이션이 Firebase를 비울 수 있음 → 검증 목적으로도 라이브 파일을 브라우저로 띄우지 말 것.
